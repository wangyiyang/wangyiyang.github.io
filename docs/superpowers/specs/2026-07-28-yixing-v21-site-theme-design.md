# 翊行代码 v2.1 全站主题改造设计

## 目的与结论

将现有博客从 v1.x 的红金、水墨与书法视觉，升级为符合「翊行代码」VI v2.1 的工业极简主题。

本次选择“主题系统换骨”方案：保留现有 Jekyll 架构、内容模型和主题组件边界，系统调整设计 token、全站排版、首页 Hero、导航、列表、侧栏、文章页与页脚。最终视觉以“精密仪器工作台”为核心意象，呈现克制、严谨、安静但处于通电状态的品牌气质。

本次不重绘 v2.1 `{翊}` Logo，也不实现 OG 图片自动生成。旧书法 Logo 资产继续保留在仓库中，但不再作为新版页头和页脚的主视觉。

## 背景

Notion 中的品牌规范已经从 v1.x 演进到 v2.1，但网站主题仍保留旧版语言：

- `tokens.css` 仍定义朱红和哑金，强调色为 `#C0392B`。
- 中文标题仍使用思源宋体。
- 首页 Hero 使用水墨风图片。
- 页头和页脚仍展示旧书法版 `{翊}` Logo。
- 组件仍存在“朱红印章”等旧版命名与表达。

这些差异不是局部配色问题，而是视觉语义冲突。只替换颜色无法消除水墨、书法、宋体和柔和卡片带来的古典气质，因此需要在不重构网站业务架构的前提下，系统替换主题表现层。

## 规范来源

本设计以以下 Notion 页面为权威来源：

- `YY · Personal Brand Prompt Kit`
- `翊行代码 · VI 核心规范`
- `翊行代码 · 个人博客规范`

核心约束：

- Brand DNA：简单、神秘、匠人之气。
- 主色系统：碳黑 `#0A0A0A`、冷白 `#FAFAFA`、终端绿 `#00E676`。
- 终端绿是状态信号，不是霓虹装饰。
- 中文统一思源黑体，英文使用 Inter，代码使用 JetBrains Mono。
- 视觉语言偏向精密仪器、现代工业设计与屏幕界面。
- 禁用书法、毛笔、飞白、印章、传统纹样、复古字体、朱红和哑金。

## 方案选择

### 未采用：仅替换颜色与字体

优点是改动最少，但旧水墨 Hero、书法 Logo、圆角卡片和布局语义仍然存在，无法形成 v2.1 品牌体验。

### 采用：主题系统换骨

保留现有内容和 Jekyll 组件边界，重塑主题 token 与关键页面组件。该方案能完整落实品牌语言，同时将回归风险控制在表现层。

### 未采用：全站重构

同时重做信息架构、Logo、OG、页面结构和内容系统的成本过高，也超出本轮“调整网站风格”的目标。

## 设计原则

### 第一性原则

网站首先是长期阅读与知识沉淀工具，其次才是品牌展示。视觉系统必须同时满足：

- 访问者能迅速识别“翊行代码”的品牌气质。
- 长文、代码、表格和图片保持稳定可读。
- 主题修改不破坏 Jekyll 内容结构和既有功能。

### 视觉原则

- 冷白承担主要留白，碳黑建立结构，终端绿只表达状态和交互。
- 灰色只能由碳黑或冷白透明度派生，不新增第四种颜色。
- 不使用渐变、霓虹、大面积彩色、厚重阴影和装饰性插画。
- 减少圆角，以细边框、网格、编号、字距和留白建立精度。
- 每个视区最多出现 1–2 个终端绿信号点。
- 个性来自不对称构图和严谨排版，不依赖复杂动画。

### 工程原则

- 不修改 `_site/`。
- 保留现有主题 CSS 分层，不另建并行主题系统。
- 优先通过 token 和现有组件类完成改造。
- 仅修改与本轮主题升级直接相关的文件。
- 不引入新的 JavaScript 动画或前端框架。
- 保持每一阶段可构建、可预览、可回滚。

## 主题基础系统

### 色彩

浅色模式：

- 页面背景：冷白 `#FAFAFA`
- 主要文字：碳黑 `#0A0A0A`
- 表面层：冷白或碳黑的极低透明度层
- 边框：碳黑 8%–16% 透明度
- 次级文字：碳黑 50%–62% 透明度
- 信号与交互：终端绿 `#00E676`

深色模式：

- 页面背景：碳黑 `#0A0A0A`
- 主要文字：冷白 `#FAFAFA`
- 表面与边框：冷白透明度派生
- 信号色保持 `#00E676`

删除朱红、哑金及其深色变体。终端绿不用于大段文字或大面积背景。

### 字体

- 中文标题与正文：`Noto Sans SC` / `Source Han Sans SC`
- 英文标题与正文：Inter
- 代码、状态和元信息：JetBrains Mono
- 中文标题使用 700 字重，正文使用 400/500 字重
- 正文基础字号 16px，行高 1.8
- 代码字号 14px，行高 1.5

移除思源宋体与旧系统宋体作为主题角色。系统字体只作为网络字体加载失败时的兼容回退。

### 形状与层次

- 小圆角控制在 2–4px；标签可保持胶囊形，但减少使用。
- 默认不使用卡片阴影。
- 组件依靠 1px 细边框、留白和背景反差分层。
- Focus 状态必须清晰，使用终端绿轮廓或下划线。

## 页面与组件设计

### 页头与导航

- 页头使用冷白/碳黑背景和底部细边框。
- 品牌入口使用“翊行代码”文字与一个终端绿方形状态灯。
- 新版页头不展示旧书法 Logo。
- 导航使用思源黑体 Medium。
- 当前项和 hover 只使用终端绿细线或文字状态，不铺绿色背景。
- 保留现有明暗主题切换能力，控件视觉改为仪器按钮风格。

### 首页 Hero

删除水墨图片，使用纯 HTML/CSS 构成不对称的黑白双空间：

- 左侧承载品牌标题、说明与现有行动按钮。
- 右侧为碳黑系统面板，展示克制的等宽状态文本和细线网格。
- 黑白分界处使用一个绿色方形或细线作为唯一主要张力元素。
- 高度约 420–560px，桌面端保持明显留白，移动端转为上下结构。
- 不新增装饰图片、纹理资源、渐变和 JavaScript 动画。

Hero 的记忆点是“安静运行的精密系统”，而不是营销大图。

### 首页文章与精选内容

- 精选内容与最新文章统一为编辑式列表，不形成卡片墙。
- 列表项使用“序号 / 标题 / 摘要 / 元信息”层级。
- 默认使用细分割线，无阴影。
- hover 时出现轻微位移或绿色侧边信号线。
- 日期、分类和状态使用 JetBrains Mono。
- 分区标题使用英文 kicker 与中文标题，但终端绿只用于 kicker 或细线之一。

### 首页侧栏

- 保留公众号、关于和专题等既有内容。
- 外观调整为设备参数面板：细边框、小圆角、紧凑标签和清晰数值。
- 二维码仍保持高可读性，不使用滤镜或品牌色覆盖。
- 移动端继续隐藏非关键侧栏内容，避免压缩正文。

### 文章页

- 文章 Header 高度约 30vh。
- 标题使用思源黑体 Bold，元信息使用 JetBrains Mono。
- 标题区域以留白与黑白对峙建立层次，不依赖 Hero 图片。
- 正文最大宽度保持 680px，行高 1.8，段落间距约 1.5em。
- 图片默认满正文宽，使用 1px 透明度边框。
- 引用块使用 4px 终端绿左线和低透明度背景。
- 代码块使用碳黑背景、冷白正文、JetBrains Mono；终端绿只用于有限语法重点或焦点状态。
- 表格、列表、行内代码和链接统一进入三色系统。
- 桌面端保留右侧浮动 TOC，当前项使用终端绿；移动端取消浮动。

### 列表页与普通页面

- 文章、专题、项目、Wiki 和普通页面共享主题 token 与排版规则。
- 页面标题保持无衬线粗体和大留白。
- 内容列表使用细线结构，不新增独立卡片体系。
- 现有页面信息架构和 Liquid 数据流不改变。

### 页脚

- 移除旧书法 Logo 的展示。
- 使用文字“翊行代码”、域名和一个终端绿状态灯。
- 版权、备案和辅助链接继续保留，但降低视觉层级。
- 不使用“印章”“朱红”等旧版命名或样式。

## 交互与动效

- hover、focus 和状态变化控制在 150–200ms。
- 只允许颜色、边框和 1–2px 位移等轻量过渡。
- 不新增滚动动画、视差、粒子、发光和复杂时间线。
- 在 `prefers-reduced-motion: reduce` 下关闭非必要过渡。
- 键盘焦点不能只依赖颜色表达。

## 响应式设计

重点断点与验收视口：

- 375px：单栏 Hero、正文和列表无横向溢出，导航可用。
- 768px：平板布局保持清晰，不出现狭窄双栏。
- 1440px：双空间 Hero、首页双栏与文章 TOC 比例稳定。

移动端处理：

- Hero 从左右对峙改为上下对峙。
- 首页侧栏回落到正文后或隐藏非关键模块。
- 文章 TOC 取消浮动。
- 标题使用 `clamp()` 控制尺寸，不硬编码多套字号。

## 数据流与组件边界

本次不改变 Jekyll 数据流：

```text
_config.yml / _data / Front Matter
  -> Liquid layouts 与 includes
  -> 现有语义化 HTML
  -> theme/main.css 聚合的主题模块
  -> 响应式页面
```

职责边界：

- `tokens.css`：品牌色、字体、间距、圆角和容器尺寸。
- `base.css`：正文、链接、代码、引用、表格等基础元素。
- `layout.css`：全局容器、网格和响应式布局。
- `components.css`：页头、导航、按钮、标签、页脚和通用组件。
- `pages-home.css`：首页 Hero、主栏和侧栏。
- `featured-posts.css`：精选内容。
- `pages-post.css`：文章 Header、正文布局、TOC 与文章尾部。
- `pages-page.css`：普通页面。
- Liquid includes：只在语义结构不支持新视觉时做最小调整。

## 异常与降级

- Google Fonts 加载失败时，回退到可读的本地无衬线字体，不影响页面功能。
- CSS 未完全加载时，语义化 HTML 仍保持正确阅读顺序。
- 深色模式读取失败时，默认使用浅色模式。
- 不依赖图片完成 Hero 构图，因此不存在关键背景图加载失败造成的首屏空白。
- 旧 Logo 文件保留，便于回溯；新版页面不依赖尚未交付的 v2.1 Logo。

## 影响与风险

### 主要风险

- 旧全局 CSS 的高优先级规则可能覆盖新主题。
- Google Fonts 的中英文字体加载可能影响首屏性能。
- 外部 Rouge 高亮主题可能与代码块三色系统冲突。
- 深色模式和历史页面类型可能存在漏网样式。

### 控制措施

- 优先在现有主题模块中覆盖，不大规模删除旧 CSS。
- 只加载实际使用的字体与字重。
- 对代码块容器和关键 Rouge token 做范围明确的主题覆盖。
- 使用代表性页面矩阵验证首页、文章页、列表页、Wiki 和普通页面。
- 每一类改动保持原子提交，便于定位与回滚。

## 验收标准

### 自动验证

- `bundle exec jekyll build` 成功。
- 新主题文件中不再出现 `#C0392B`、`#D4A84B` 等旧红金 token。
- 主题不再加载 `Noto Serif SC`。
- 首页不再引用 `images/yixing-hero-banner.jpg`。
- 新版页头和页脚不再引用旧 `images/yixing-logo.svg`。

### 页面验证

- 首页、文章页、文章列表页和普通页面在浅色与深色模式下均可读。
- 375px、768px、1440px 视口无横向溢出。
- Hero 黑白对峙明确，终端绿保持小面积信号用途。
- 导航、链接、按钮和主题切换具备清晰 hover 与键盘 focus。
- 正文宽度、行高、代码块、引用、表格和图片符合博客规范。
- 移动端导航、正文与文章 TOC 行为正确。
